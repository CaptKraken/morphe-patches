# Native playlist queue

Adds an in-memory video queue to YouTube20.51.39,21.16.256 and21.20.405 using its existing playlist panel, fullscreen playlist view, row gestures, player controls and notification controls. Played videos remain in the list. Play next inserts after the playing entry; Play last appends. Opening another regular video inserts and selects it after the current entry.

YouTube owns rendering, playback sequencing, current selection and repeat. Shuffle is a local command: the extension keeps the playing occurrence first, shuffles the remaining rows using the same Collections.shuffle utility as the native engine, and publishes that order for native sequential playback. The extension supplies local rows, tracks ownership and pending navigation, and mirrors native selection in an immutable snapshot. Patch-time Kotlin discovers native references and adds small typed bridges; Java owns runtime behavior. Stable diagnostic/resource/signature relationships identify hooks. Ordinary/account playlists and unrelated commands retain native callbacks.

Individual rows reuse native Save, Download and Share actions. The queue header saves the full ordered list through the native picker and New playlist dialog. Save mutation/confirmation state belongs to that queue-launched picker/callback; the normal player Save button is not globally repurposed. Existing-playlist Save Undo removes only returned added-entry IDs.

Removal and Clear queue have bounded, queue-specific Undo capabilities. **Clear queue Undo is an intentional addition**, retained even if Premium does not offer it. Playback continues through clearing/restoration. Queue state is not persisted across process restarts.

This remains a separate alternative to Morphe's Add to queue. If that patch is installed and its Local queue setting is enabled, Morphe takes priority: native starts/reattachment are blocked and an active native session is detached through its existing clear transaction. Morphe stored items/settings remain untouched. Turning the setting off does not revive stale native state.

Supported targets are20.51.39,21.16.256 and21.20.405, verified by recorded real-APK checks and user-reported phone tests. The whole patch remains experimental; no additional Premium backend entitlement is claimed. The generated existing-playlist Save confirmation uses5seconds normally and retains native Undo/accessibility behavior; the user reported the shorter confirmation working.
